# 自动更新机制（Fugu 三期·批9）

> **范围警告：这是开发源码/依赖巡检器，不是桌面安装包自动更新。** 它只生成上游变化报告，不下载或安装纳川版本，
> 也不属于 `0.2.0 early-access` 的 Ed25519 签名更新通道。本次没有、也不得按本文示例注册计划任务；是否启用巡检必须
> 由机主另行明确授权。

**一句话**：一个只「看」不「改」的哨兵脚本——每周替你扫一遍「上游有没有新东西」，
汇成一份报告落盘、可选推到你飞书。**发现 ≠ 应用**：它绝不自动改代码、不自动升级依赖、不自动接入新模型；
想采纳哪一项，你把报告里那一行复制给纳川里的我，由我动手。

---

## 它扫什么（四路探测器，各自独立，一个挂了其它照跑）

| # | 探测 | 数据来源 | 产出 |
|---|------|----------|------|
| ① | **新模型** | 各 `openai_compat` 连接（读 `data/connections.json`）拉 `{base_url}/models` | 「上游有、本地还没接入」的新模型 id |
| ② | **Python 依赖** | `uv pip list --outdated`（失败降级 `pip`） | 可升级的包 top 15（当前→最新） |
| ③ | **npm 依赖** | `npm outdated --prefix desktop` | 可升级的前端包 top 15 |
| ④ | **上游动态** | `gh api` 盯 4 个仓库的 latest release / 最新 commit | 与上次快照比，**只报有变化**的 |

盯的上游仓库：`SakanaAI/fugu`、`trotsky1997/OpenFugu`、`FoundationAgents/OpenManus`、`lm-sys/RouteLLM`。

---

## 怎么手动跑

在仓库根（`D:\大模型聚合器`）：

```powershell
.\.venv\Scripts\python.exe scripts\watch_updates.py            # 跑一遍，报告落 data/ 并打印到屏幕
.\.venv\Scripts\python.exe scripts\watch_updates.py --feishu  # 额外把报告摘要推给机主飞书
.\.venv\Scripts\python.exe scripts\watch_updates.py --json     # 机器可读 JSON（给自动化/调试）
.\.venv\Scripts\python.exe scripts\watch_updates.py --dry      # 不发任何网络请求（自检管道用）
```

也可直接双击 `安装与维护\手动检查上游更新.cmd`。巡检器不再解析 PATH：Python 依赖栏目优先使用当前项目
`.venv`；uv/gh 只有同时提供受保护启动器注入的绝对路径与 SHA-256 才启用；npm 还必须同时绑定 Node、
`npm-cli.js` 及完整 npm 代码树摘要。任何证据缺失只会让对应栏目明确跳过，不会临时下载工具或改用同名命令。

## 报告在哪

- **报告**：`data/update_report_YYYYMMDD.md`（每天一份，四节；某节没更新也会写「(无更新)」）。
- **快照**：`data/watch_state.json`（记各上游仓库上次看到的 release tag / commit sha；
  首跑全报并落快照，之后只报「跟快照不一样」的）。
- 两者都在 `data/`（已 gitignore，不会进版本库）。

报告结尾会附一句：**想应用哪项，把那一行复制给纳川里的我即可**（例如「接入 agnes-3.0 模型」「升级 fastapi」「看下 fugu 新 release」）。

## 无人值守运行：当前禁止

旧版曾给出“管理员隐藏 PowerShell + `ExecutionPolicy Bypass` + PATH 上的 `uv` + 可写仓库脚本”的
计划任务示例。该方案已经废弃并删除：仓库内脚本可被同一用户或智能体改写，下一次周期触发就会把源码写权限
升级成持久代码执行权限，还可能继承模型与飞书凭据。

当前 `watch_updates.py` **只允许人工、前台、显式运行**。本机也已核验不存在名为“纳川-自动更新哨兵”的任务，
全部计划任务动作均未引用该脚本。未来若恢复无人值守巡检，必须重新实现为受保护安装目录中的不可变闭包，至少满足：

- 非管理员低权限服务账户，固定绝对解释器和脚本路径；
- 运行前闭集 manifest、SHA-256、签名/来源、路径重解析与 ACL 复验；
- 最小环境，不继承 PATH、代理、模型密钥或桌面会话凭据；
- 有界网络、超时、锁、不可变回执和失败关闭；
- 先通过独立安全回归与真实 smoke，再由机主显式启用。

这与桌面应用的 Ed25519 签名自动更新是两条完全不同的信任链；禁止用本开发巡检脚本替代桌面更新器。

## 飞书推送（`--feishu`）

- 读 `gateway/config.py` 里的 `feishu_app_id` / `feishu_app_secret` / `feishu_owner_open_id`（即你自己 bot 的凭证 + 你的 open_id）。
- 三者齐全才推：走 `tenant_access_token` → `im/v1/messages`（`receive_id_type=open_id`），把**报告摘要**（每节第一行，总 <500 字）发给你自己。
- 缺任一项 → 明确打印「未配置飞书，跳过推送」；推送失败只警告，**不影响报告落盘**。

## 设计哲学：发现 ≠ 应用

- **只读、只报，绝不自动改**：不 `git`、不改 `catalog.py`、不 `pip/npm install`、不动连接配置。
- **人工一键授权**：所有采纳动作都由你看报告后决定，一句话交给纳川里的我执行。
- **安全边界**：连接的 `api_key` **只进 /models 请求头**，绝不写进报告/日志/快照/JSON；
  对外只有三种请求——各连接的 `/models` GET、`gh api`（只读）、可选飞书推送（你的 bot 发给你自己）。
- **全程降级容错**：任一探测器崩了，其余照跑、报告照出；无 `gh`、无网、无 `desktop/` 都能安全跳过。
