# ADR-0015：共享核心、三版本独立发布通道

- 状态：Accepted
- 日期：2026-08-25
- 取代范围：修订 ADR-0013 中“桌面发行整章作废”的过度结论；CLI 仍是开源源码版主入口，桌面与企业发行恢复为受门禁的正式产品目标。

## 背景

纳川同时需要技术用户可审计的开源源码版、普通用户低摩擦桌面版和企业受管商用版。如果三者复制源码或独立
维护版本，安全修复、模型连接、协作协议和数据迁移会快速漂移；如果三者共用一个更新通道，企业策略又可能被
社区更新覆盖或发生跨通道降级。

## 决策

1. `pyproject.toml`、`desktop/package.json` 和 `config/distribution-channels.v1.json` 在每次发布中必须使用同一核心版本。
2. 三个版本都从同一核心源码构建；企业差异通过受权限内核控制的策略/连接器/控制面实现，不复制或私自修改核心。
3. 三个通道相互独立：`community-source-alpha`、`stable-desktop-win-x64`、`enterprise-stable-win-x64`。
4. 社区版用不可变 GitHub commit 和 `OPEN_SOURCE_SNAPSHOT.json` 闭包校验安装；不把源码交付伪装成 Authenticode。
5. 桌面与企业 Windows 安装包必须 Authenticode 签名、带可信时间戳，并通过签名更新信封、反回滚和干净机验收。
6. 修复从共享核心进入三版，但升级放量独立；社区验证通过不自动批准桌面或企业生产发布。
7. `scripts/verify_distribution_contract.py` 是 CI/安装时共同执行的故障关闭门禁。

## 后果

- 一次核心修复能进入全部版本，减少“开源版修了、商用版仍旧”的分叉。
- 普通客户最终获得签名桌面安装器和应用内更新；技术用户不必等签名即可使用源码入口。
- 企业版仍需单独完成身份、租户、RAG 权限、部署、审计、备份和 SLA 验收，不能借共享核心提前宣称就绪。
