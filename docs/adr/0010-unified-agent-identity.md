# ADR-0010：统一“纳川”身份，后台按能力编排

- 状态：拟采用（当前生产化审计完成后实施）
- 日期：2026-07-17
- 关联：ADR-0001、ADR-0004、`STRATEGIC_GOALS.md` 第 2 项

## 结论

纳川面向个人和企业都采用“一个前台身份、一个任务状态、后台多能力协作”的产品形态。

用户只需向“纳川”交办目标。模型选择、角色分工、工具调用、独立复核、失败升级和工作流选择由后台完成；具体模型、辩论和流水线配置仅作为高级功能保留，不再是普通用户完成任务的必经步骤。

这里的“一个身份”不是一个拥有全公司数据权限的万能账号，而是统一产品身份。实际执行必须按租户、用户、频道、任务和工具签发最小权限能力，并隔离记忆和审计域。

## 为什么适合纳川

纳川已有统一 Turn Engine、舰队路由、工具 Agent、独立互审、长期任务状态和多渠道适配的基础。当前缺口不是再增加一批角色型 Agent，而是让已有能力在同一入口、同一任务和同一权限链下真正协作。

个人用户得到的是“不选模型也能办成事”；企业用户得到的是“同一入口跨系统完成业务，但每一步仍可授权、审批、追踪和撤销”。

## 必须保留的边界

1. 系统真源仍是 CRM、ERP、Git、工单、文档库等原系统；纳川只编排并回写，不复制出第二套业务真相。
2. 共享任务状态不等于把完整上下文广播给所有模型。每个执行单元只获得完成本步所需的最小上下文。
3. 发起模型不参与自己的独立互审；它接收其他模型的审查结果后做有证据的总结。
4. 写操作、付款、发布、删除、对外发送等高风险动作必须经过能力票据、审批、幂等账本和结果验真。
5. 企业数据按租户、组织、频道和角色隔离；跨域访问必须显式授权并写入审计日志。
6. 用户能够看到任务进度、依据、实际执行模型/工具和最终状态，但不必参与后台路由。

## 分期方案

### A. 统一入口（当前审计收口后）

- 桌面、微信、飞书和 HTTP 全部进入同一 Turn Engine。
- 默认只展示“纳川”；具体模型与编排面板移入高级模式。
- 同一请求只生成一个 `turn_id/task_id`，所有模型调用、工具动作、审批和交付都绑定该标识。
- 统一进度、超时、取消、重试和 Outcome 语义。

### B. 后台能力路由

- 将后台选择对象从“固定岗位 Agent”改为版本化能力：规划、检索、编码、数据分析、媒体、业务连接器、独立复核等。
- 路由器根据任务、权限、成本、延迟、历史评测和工具可用性选择模型与能力。
- 复杂任务使用共享 WorkGraph；各节点获取最小上下文投影，产物进入证据账本。
- 路由失败、模型失败或验证失败可升级，但不得假装完成。

### C. 个人版与企业版权限面

- 个人版：本机身份、个人连接器、明确授权、隐私记忆、费用上限。
- 企业版：SSO/OIDC（需要时再扩展 SAML）、组织与频道映射、RBAC/ABAC、连接器服务账号、密钥库、审批流、审计、保留期、DLP 和预算配额。
- 企业管理员定义“纳川在什么范围看什么、能做什么”；模型本身不能扩大权限。

### D. 组织协作与持续改进

- 支持公开协作线程、多人补充约束和任务接力，但私有频道/私有记忆默认不外泄。
- 成功任务沉淀为可版本化 skill、流程和评测案例；上线前必须回归验证。
- 与长城任务、商业流程和模型改进三个长期目标统一设计，当前不提前实施。

## 验收标准

- 普通用户完成典型任务无需选择模型或角色。
- 同一任务跨渠道继续时状态、权限和证据不丢失，也不会重复执行副作用。
- 任一后台模型只能看到获授权的上下文，越权读取和跨租户混用测试必须失败。
- 每个外部写动作可追溯到用户、任务、能力票据、审批和验真收据。
- 独立评测证明统一入口的成功率、交付时间或用户操作步数优于角色型入口，且成本和风险不恶化。

- Sierra 将内部角色型 Agent 合并为一个 Pinecone 入口，同时用继承用户权限、逐工具策略和审计控制风险：<https://sierra.ai/uk/blog/ai-pilling-our-company-lessons-learned>
- Anthropic Claude Tag 采用频道内统一协作身份，但明确要求按管理员配置隔离工具、数据和记忆域：<https://www.anthropic.com/news/introducing-claude-tag?invite=1>
- Shopify River 在公开 Slack 线程协作，并将共享线程、可复现环境、skills 和评测基础设施作为关键前提：<https://shopify.engineering/under-the-river>
